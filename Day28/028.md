Day 28 of 100 Days of DevOps challenge on KodeKloud.

The task involved working with the beta repository, which had two branches: master and feature. A developer was still working on the feature branch, but one specific commit with the message Update info.txt needed to be moved into the master branch.

Instead of merging the entire feature branch, I used git cherry-pick to apply only the required commit to master. After verifying the changes, I pushed the updated master branch to the remote repository.

Git cherry-pick is extremely useful when you need to selectively apply a specific commit from one branch to another without bringing along all the other ongoing work.

Good to Know?

Cherry-Pick Fundamentals
Purpose: Apply specific commits from one branch to another
Selective: Choose individual commits, not entire branches
New Commit: Creates new commit with same changes
Preserve Author: Maintains original author information

Cherry-Pick Use Cases
Bug Fixes: Apply hotfixes to multiple branches
Feature Backporting: Bring features to older versions
Selective Merging: Include specific changes without full merge
Release Management: Pick commits for release branches

Cherry-Pick Options
Single Commit: git cherry-pick commit-hash
Multiple Commits: git cherry-pick hash1 hash2
Range: git cherry-pick start-hash..end-hash
No Commit: git cherry-pick --no-commit - Stage without committing
