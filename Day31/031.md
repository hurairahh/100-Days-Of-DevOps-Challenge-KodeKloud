Day 31 of 100 Days of DevOps challenge on KodeKloud.

The task involved working with the media repository, where a developer had previously stashed some in-progress changes. I had to inspect the available stashes, restore the changes from stash@{1}, commit them, and push the changes to the origin repository.

Git stash is useful when you need to temporarily set aside uncommitted work while keeping the working directory clean. It allows developers to switch tasks or branches without having to create an incomplete commit.

Good to Know?

Git Stash Purpose
Temporary Storage: Save work-in-progress without committing
Branch Switching: Clean working directory for branch changes
Emergency Fixes: Quickly switch to fix urgent issues
Experiment: Try different approaches without losing work

Stash Operations
Save: git stash or git stash push -m "message"
List: git stash list - Show all stashes
Apply: git stash apply stash@{n} - Restore without removing
Pop: git stash pop - Apply and remove latest stash
